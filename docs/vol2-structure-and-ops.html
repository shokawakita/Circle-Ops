Section 01

先に直すべき前提

構造の話

「無償ボランティアが手伝う」と「主宰者が利益を得る」は、長くは同居しません。法的には無報酬である限り雇用の問題は起きません（Vol.1 参照）。壊れるのは人間関係のほうです。3ヶ月目くらいに「自分は何のためにやっているんだろう」が必ず来ます。趣味の集まりならそれでも続きますが、あなたの売上が見えている場では続きません。

なので還元の形を、利益が出る前に決めておく必要があります。後から決めると「利益が出たから分ける」になり、必ずこじれます。

運営メンバーへの還元 ── 4つの型

型内容労働法リスク向いている段階
A. 現物還元 参加費免除＋当日の飲食代・交通費を実費負担。金銭の報酬なし。 なし 立ち上げ〜月4回程度まで。ここから始める。
B. 都度の業務委託 イベント単位で「今回の受付、5,000円で」と都度合意。回数も金額も固定しない。 要注意 月商が安定してから。固定化・定額化すると雇用と評価されうる。
C. 共同主催／売上シェア 各自が自分の企画を持ち、その回の粗利を配分。指揮命令が生じない。 低い 企画を回せる人が2人以上いる段階。最も健全に伸びる形。
D. 法人化して内部化 合同会社の社員（出資者）や一般社団の理事にして、役員報酬または利益配分。 別枠 年商が立ち、共同経営者と呼べる人ができてから。

おすすめの進み方は A → C → D。B は一見ラクですが、「毎回同じ人に同じ金額を払う」に着地しがちで、そこが一番グレーです。C（共同主催）は法的にきれいなだけでなく、企画の幅が勝手に広がるという副次効果があります。カフェ巡りが得意な人、ボドゲに強い人、それぞれに回を持たせる形です。

Section 02

体制の選択肢

日本で取りうる器は実質5つです。コストは登記実費の目安で、司法書士に依頼すると各+5〜10万円かかります。

01

任意団体のまま（何もしない）

初期 0円 ／ 維持 0円

届出も登記もなし。今の状態です。売上が小さいうちはこれで完全に合法かつ十分です。

Good
  • コストも手間もゼロ
  • いつでも始められる／やめられる
Bad
  • 契約も債務も代表個人に無限責任で帰属
  • 屋号口座が作りにくく、会計が個人と混ざる
  • 経費を落とせず、節税の余地がない

判定：最初の3〜6ヶ月はこれでいい。ただし「黒字を目指す」なら卒業前提の器。

02

個人事業主（開業届＋青色申告）

初期 0円 ／ 維持 0円まずここ

税務署に開業届を出すだけ。費用ゼロで、黒字化に必要なものがほぼ全部手に入ります。屋号付き口座が開け、会場費・備品・通信費を経費にでき、青色申告なら最大65万円の所得控除、赤字は3年繰り越せます。

Good
  • コストゼロで税務上の武器が揃う
  • 屋号名義の口座・決済が使える
  • やめるのも廃業届1枚
Bad
  • 責任は無限（個人に帰属）
  • 法人格が要る取引には対応できない
  • 会社員の場合、住民税経由で勤務先に伝わる可能性がある

判定：黒字化を目指すなら、最初にやるべきはこれ一択。開業から1ヶ月以内に開業届、2ヶ月以内に青色申告承認申請（期限を逃すと青色はその年使えません）。

03

合同会社（LLC）

初期 約6万円 ／ 維持 年7万円〜

登録免許税6万円のみ（定款認証が不要なので株式会社より格段に安い）。1人で設立でき、有限責任。維持費として、赤字でも法人住民税の均等割が年7万円ほどかかります。

Good
  • 有限責任（個人資産と切り離せる）
  • 法人契約・請求書・協賛の受け皿になる
  • 役員報酬や経費で税負担を設計できる
  • 共同経営者に持分を持たせられる
Bad
  • 赤字でも年7万円＋会計の手間
  • 社会保険が原則強制加入（役員報酬を出す場合）
  • 畳むのにも数万円と手続きがかかる

判定：利益が出てから。目安は課税所得が年800万円前後を超えたら税率面で有利。ただし金額より「法人でないと取れない話が来たとき」が実際の引き金になることが多い。

04

一般社団法人（非営利型）

初期 約11〜12万円 ／ 維持 年7万円〜

設立時に社員2名以上が必要。要件を満たして「非営利型」になると、収益事業から生じた所得のみが課税対象となり、会費や寄付の扱いが有利になり得ます。ただし要件は細かく、税理士の確認が実質必須です。

Good
  • 「みんなのコミュニティ」という建て付けにできる
  • 自治体の助成金・後援に乗りやすい
  • 公共施設や学校との連携で信用が効く
Bad
  • 剰余金を自分に配当できない（役員報酬は可）
  • 社員2名以上・定時社員総会など運営が重い
  • 非営利型の要件維持に専門家コストがかかる

判定：「個人の事業」ではなく「地域のコミュニティ」として育て、行政や企業と組みたくなったときの選択肢。今の段階では重すぎます。

05

株式会社 ／ NPO法人

株式 約20〜25万円 ／ NPO 認証に数ヶ月

株式会社は信用度が最も高い一方、設立費用が合同会社の3〜4倍。外部から出資を受ける予定がなければ、サークル事業で選ぶ理由はほぼありません。NPO法人は社員10名以上・所轄庁の認証・毎年の事業報告と、負荷が段違いに重い。

判定：いずれも現時点では検討不要。将来「出資を受ける」「公益活動として補助金で回す」となったときに初めて土俵に乗ります。

Section 03

推奨ルートと切り替えライン

結論としては「任意団体 → 個人事業主 →（必要になったら）合同会社」の3段階です。最初から法人を作ると、年7万円の均等割と会計の手間が、まだ何も証明されていない事業にのしかかります。

  1. 1

    Now → 半年 ／ 任意団体

    器は作らず、まず売上と再現性をつくる

    • 実費割り勘か、粗利の乗った定額会費かを決めて、まず10回開く
    • 専用の口座・ウォレットを分け、収支を1行ずつ記録する（＝後で開業届を出すときの根拠になる）
    • この期間の目標は利益額ではなく「同じ形式を3回まわして、参加者が戻ってくるか」
  2. 2

    黒字が見えた時点 ／ 個人事業主

    開業届を出す（＝実質ここが「組織化」の本番）

    • 引き金：月の粗利が安定して出る／年間の所得が20万円を超えそう／経費が増えてきた
    • 開業届＋青色申告承認申請を提出。屋号名義の口座を開設
    • 会計ソフトを1つ入れる（freee・マネーフォワード等、年1万円前後）
    • 運営メンバーへの還元を A（現物）から C（共同主催・売上シェア）へ移行
  3. 3

    引き金が来たら ／ 合同会社

    金額より「できないことが出てきたか」で判断する

    • 課税所得が年800万円前後を超えた（税率面のメリットが出る）
    • 企業協賛・法人向けイベント受託など、法人でないと契約できない話が来た
    • 共同運営者に持分を持たせて、対等な経営体にしたくなった
    • 参加人数や企画の規模が大きくなり、有限責任にしておきたいと感じた
分岐

もし途中で「これは自分の事業ではなく、地域のコミュニティとして育てたい」「行政や学校と組みたい」「助成金を取りたい」と思ったら、そこで合同会社ではなく一般社団法人（非営利型）に分岐します。判断軸は税率ではなく、利益を自分のものにしたいか、団体のものにしたいかです。ここは早めに自分の中で決めておくと、後の意思決定が全部速くなります。

会社員の場合の注意

本業がある場合、①就業規則の副業規定を先に確認、②確定申告時に住民税を「自分で納付」にする（給与天引きだと住民税額の差で勤務先に把握されうる。ただし完全に防げるわけではありません）、③法人を作って役員報酬を出すと社会保険の二重加入手続きが発生する ── の3点を先に潰しておいてください。②③は法人化を先送りする実務的な理由になります。

Section 04

黒字化の収益構造

「参加者に喜んでもらった上で利益を出す」ためには、単発イベントの参加費だけで稼ごうとしないことが肝心です。参加費を上げると、喜んでもらうことと利益が正面から対立します。

まず単発イベントの現実的な数字

項目ボードゲーム会特別企画（貸切）
参加者10名20名
参加費2,000円4,000円
売上20,000円80,000円
会場・原価−12,000円−55,000円
粗利8,000円25,000円
運営工数約4時間約12時間
時間あたり2,000円2,080円

ここが構造的な問題です。月4回まわしても粗利は3〜5万円で、工数は20時間近い。参加費を3,000円に上げれば粗利は倍ですが、「気軽に来られる場」というコンセプトが崩れます。単発参加費は事業の土台であって、利益の源泉にはできない。だから3階建てにします。

収益の3階建て

1FFLOW

単発イベントの参加費 ── 入口であり、信頼をつくる場

粗利率30〜40%を目安に、原価に対して無理のない価格をつける。ここは利益を取りに行かず、体験の質に全振りする。ここが良ければ2Fが埋まり、悪ければ何をやっても埋まりません。

2FSTOCK

月額メンバーシップ ── 黒字化の主役

月500〜1,500円で、優先予約・参加費割引・限定イベント・オンラインの交流枠など。100人 × 1,000円で月10万円が、開催の有無にかかわらず入る。これが工数と売上を切り離す唯一の方法です。ただし1Fで「この人たちとまた会いたい」が積み上がっていないと1人も入りません。

3FLEVERAGE

コンテンツと法人案件 ── 場を持っているから成立するもの

note の有料記事・メンバーシップ（コミュニティ運営のノウハウ、イベント設計論）、カフェや店舗とのタイアップ・送客、企業の懇親会やチームビルディングの受託。3Fは1F・2Fの副産物なので、狙って作るものではなく、たまったものを換金する場所です。

マイルストーン目安
  • 6ヶ月：月商5万円・収支トントン。「同じ人が3回来る」が起きていれば成功。
  • 12ヶ月：月商15〜20万円、粗利10万円。メンバーシップを開始する。
  • 24ヶ月：ストック収入で固定費を賄える状態。ここで初めて法人化が現実的な検討に乗る。

Section 05

Claude Code 運用設計

Claude Code をチャット相手として使うのではなく、「サークル運営 OS」のリポジトリを1つ作り、そこに知識と手順を溜めるのが本命の使い方です。ブランドのトンマナ、参加規約、過去の募集文、会場リストがリポジトリにあると、毎回ゼロから説明しなくてよくなります。

リポジトリ構成

circle-ops/
├ CLAUDE.md              # 常時読まれる前提：コンセプト・トンマナ・禁止事項
├ .claude/
│  ├ skills/                # /コマンドとして呼び出す定型業務
│  │  ├ event-new/          # 企画→募集文・台本・収支・告知まで一括
│  │  ├ event-close/        # 開催後の締め（収支確定・振り返り・レポ下書き）
│  │  ├ sns-week/           # 週次のSNS投稿カレンダー
│  │  ├ blog-report/        # イベントレポ記事（note-team と連携）
│  │  └ kpi-monthly/        # 月次サマリと収支レポート
│  └ settings.json          # Notion / Google Drive MCP の権限設定
├ brand/
│  ├ concept.md             # Vol.1 で決めた一文コンセプトと対象
│  ├ voice.md               # 言い回し、絵文字の使い方、NGワード
│  └ rules.md               # 参加規約（募集文に毎回差し込む）
├ venues/
│  └ venues.md              # 会場台帳：店名・エリア・収容・費用・団体可否
├ events/
│  └ 2026-09-13-boardgame/
│      ├ plan.md  recruit.md  script.md  pl.md  retro.md
└ content/                  # ブログ・note の下書き置き場
最重要の運用ルール

参加者の個人情報はリポジトリにも Notion にも入れない。扱うのはニックネームと参加回数まで。本名・連絡先は申込フォーム（Googleフォーム等）側に置いたままにして、必要なときだけ見る。Vol.1 の個人情報の項目と直結します。この線を最初に引いておかないと、後から分離するのは非常に面倒です。

作るべきスキル（＝/コマンド）

/event-new

イベント作成 ── 企画名を渡すと、当日までの一式が揃う

これが一番効きます。今まで2〜3時間かかっていた準備が、確認と手直しだけになります。

  • 募集文（規約・キャンセルポリシー・持ち物を自動で差し込み、トンマナは brand/voice.md 準拠）
  • 収支シミュレーション（会場台帳から原価を引いて、損益分岐人数を算出）
  • 当日の進行台本（Vol.1 の90分テンプレを企画に合わせて調整）
  • 持ち物・準備チェックリスト、リマインド文の下書き
  • Notion のイベントDBにページを作成し、Instagram / X 用の告知文まで生成

例：「/event-new 10月下旬に横浜でハロウィンのボドゲ会、12人、参加費2,500円」

/event-close

開催後の締め ── 振り返りを「やらずに終わる」を防ぐ

  • 実際の参加人数と支出を伝えるだけで、収支を確定して Notion に反映
  • アンケート結果を要約し、次回への改善点を3つに絞って提示
  • その場でイベントレポのブログ下書きまで生成（記憶が新しいうちに書けるのが最大の利点）
  • 参加者へのお礼文＋次回告知のテンプレ
/sns-week

SNS活動 ── 週次でまとめて作り、投稿は手で出す

SNSは「毎日考える」のが続かない原因なので、週1回まとめて7日分作る形にします。

  • Instagram のフィード投稿案・キャプション・ハッシュタグ（エリア系／興味系／サークル系のバランスを取る）
  • ストーリーズのネタ（準備風景、会場の下見、次回予告）
  • X 用の短文、投稿する曜日と時間帯の提案
  • 掲載NGの参加者がいる回は、写真の使い方に注意喚起を出す

例：「/sns-week 来週はボドゲ会の告知が主。先週のランチ会の写真あり」

/blog-report

ブログ作成 ── 既存の note チームをそのまま流用できる

お手元の Note-Team リポジトリには、リサーチ→構成→執筆→校閲→SEO→マネタイズの7役がすでに揃っています。サークルのイベントレポと集客記事は、この仕組みにそのまま乗せられます。

  • 集客記事（「横浜 ボードゲーム 初心者」等の検索流入狙い）＝ note-researcher → note-planner → note-writer
  • 公開前に note-editor で規約・薬機法・肖像権のチェックを通す
  • note のメンバーシップ設計は note-monetizer が担当（3F の収益に直結）
/kpi

月次サマリ ── 見る数字は3つだけ

  • Notion のイベントDBを読んで、参加人数・リピート率・粗利を集計
  • 前月比と、伸びた／落ちた要因の仮説
  • 翌月の開催計画のたたき台

Notion 連携 ── 4つのデータベース

DB主なプロパティ役割
イベント 日付／ステータス（企画・募集中・開催前・完了）／会場／定員／申込数／参加費／売上／原価／粗利 すべての中心。/event-new が作り、/event-close が閉じる。
会場台帳 店名／エリア／最寄駅／収容人数／費用／団体利用可否／予約方法／担当者メモ 地味だが最も効く。原価計算と会場選定が一瞬で終わる。
参加者 ニックネーム／初参加日／参加回数／写真掲載可否／メモ
※本名・連絡先は入れない		 リピート率の把握と、運営メンバー候補の発見に使う。
コンテンツ 種別（SNS/ブログ/note）／公開予定日／状態／関連イベント／実績数値 発信の抜け漏れ防止。/sns-week と /blog-report の出力先。

Notion の MCP 連携はこのセッションで既に使える状態なので、DBの作成そのものを Claude Code にやらせられます。手で作る必要はありません。

Section 06

導入の順番

全部を一度に作ると使わないまま腐ります。1つ作って3回使ってから次を徹底してください。

  1. 1

    Week 1

    CLAUDE.md と brand/ だけ作る

    • Vol.1 で決めたコンセプト・対象・規約・トンマナを書き出す
    • これがあるだけで、以降の出力の精度が段違いに変わる
  2. 2

    Week 2

    /event-new と会場台帳

    • 最も工数を食っている部分から自動化する
    • 実際に1回イベントを作ってみて、出力を手直しした差分をスキルに反映する
  3. 3

    Week 3–4

    Notion の4DBと /event-close

    • ここまでで「作って・開いて・締める」が1周する
    • データが溜まり始めるので、KPIが見えるようになる
  4. 4

    Month 2 以降

    SNS・ブログ・定期実行
