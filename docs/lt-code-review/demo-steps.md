# デモ再現手順とキャプチャ撮影ポイント

手元の Mac で以下をなぞると、LTで見せる画面がそのまま再現できます。
**撮影は6枚**。Keynote に貼るのはこの6枚だけです。

## 準備

```
git clone <このリポジトリのURL> circle-ops
cd circle-ops
git checkout claude/claude-code-lightning-talk-etswnd
```

ターミナルは**文字を大きく**しておきます（会場の後ろから読めません）。
- ターミナル > 設定 > プロファイル > テキスト > フォントサイズ **18pt 以上**
- ウィンドウは横幅を狭めに。横に長いと投影時に文字が小さくなります

---

## STEP 1 — 題材のコードを見せる

```
cat tools/kpi_summary.py
```

60行の Python スクリプトです。`finance/ledger.csv`（収支台帳）を読んで、
その月の売上・支出・粗利を出すだけのもの。

> 📸 **キャプチャ①**：`summarize()` 関数のあたり（20〜35行目）。
> 全部は入らないので、**バグのある部分だけ**を映す。
> エディタで開いて撮ったほうがシンタックスハイライトが効いて読みやすいです。

---

## STEP 2 — 実行する。エラーは出ない

```
python3 tools/kpi_summary.py 2026-01
```

実際の出力：

```
=== 2026-01 の収支 ===
売上      : 20,000 円
支出      : -16,800 円
粗利      : 36,800 円
1件あたり : 36,800 円
```

台帳の中身は「売上 20,000 / 会場費 12,000 / 分配 4,800」なので、
**手元に残るのは 3,200 円**。なのに 36,800 円と表示されています。
支出を引かずに足してしまっているためです。

**エラーは1つも出ません。** ここがこのデモの肝です。

> 📸 **キャプチャ②**：この実行結果。
> 「36,800 円」の部分に、Keynote 側で後から赤い囲みを付けます。

---

## STEP 3 — `/code-review` と打つだけ

Claude Code を起動して、スラッシュコマンドを1つ打ちます。

```
claude
```

```
/code-review
```

引数は要りません。**今の変更差分を自動で見つけてレビューしてくれます。**

> 📸 **キャプチャ③**：`/code-review` と入力した瞬間の画面。
> スラッシュを打つとコマンド候補が出るので、その候補リストごと撮ると
> 「他にもコマンドがあるんだ」が伝わって親切です。

> 📸 **キャプチャ④**：レビュー実行中の画面（ファイルを読んでいる様子）。
> 動いている感じが出るので1枚あると良いです。省略可。

## STEP 4 — 指摘が返ってくる

実際に返ってきた指摘は **9件**。全文は `review-result.md` にあります。

> 📸 **キャプチャ⑤**：指摘の一覧が並んでいる画面。
> 全部は読めなくてよいです。「こんなに出た」という**量**を見せるための1枚。

> 📸 **キャプチャ⑥**：指摘のうち **2つ目**（利益分配の扱いについての指摘）を
> 拡大したもの。ここがLTの山場なので、この1枚だけは文字が読める大きさで。

---

## 撮影のコツ

- macOS の `Shift + Command + 4` → `Space` でウィンドウ単位のきれいな影付きキャプチャが撮れます
- 影がKeynoteで邪魔なときは、`Space` を押した後に `Option` を押しながらクリック
- **ターミナルの背景は明るいテーマ**にしたほうが、投影時に読めます（黒背景は飛びます）
- 個人情報・APIキー・他の作業中タブが映り込んでいないか、貼る前に必ず確認

## 補足：発表後に「自分でも試したい」と言われたら

このデモは特別な準備は要りません。相手の手元のリポジトリで、
何か変更を加えた状態で `/code-review` と打つだけで同じことが起きます。
