## 1. 符号の反転 — `kpi_summary.py:33` ★スライド5で使う

台帳の支出はもともとマイナスの数値で記録されている。
そこに `expense += amount` としているので支出の合計がマイナスになり、
`income - expense` で**支出を利益に足してしまっている**。

> 実際の台帳で動かすと 支出 -16,800 / 粗利 36,800 と出るが、正しくは 8,000。

## 2. 利益分配の扱いがルールと違う — `kpi_summary.py:30` ★スライド8で使う

`share`（利益分配）の行が支出として集計されている。
しかし `finance/profit-share.md` では「粗利 = 売上 − 原価、分配は粗利から支払う」
と定義されている。**符号を直しても、粗利は 8,000 であるべきところが 3,200 になる。**

> リポジトリ内の別ファイル（運営ルールの文書）を読んだ上での指摘。
> ここがこのLTで一番伝えたいポイント。

## 3. ゼロ除算 — `kpi_summary.py:45`

売上の行が1件もない月（例：`2026-02`）を指定すると `profit / participants` で
ゼロ除算になり、クラッシュする。

## 4. 引数なしで実行すると落ちる — `kpi_summary.py:40`

## 5. 月の指定が雑 — `kpi_summary.py:19`

「その月の収支」として表示される**。`2026-1`（ゼロ埋めなし）だと1件も一致せず、
指摘3のゼロ除算に落ちる。

## 6. ファイルを閉じていない / パスが相対 — `kpi_summary.py:16`

## 7. 変数名が実態と違う — `kpi_summary.py:44`

将来この数字を「参加者数」として表示してしまう事故のもとになる。
