# Notion イベントデータ作成ルール

`TEST_Event_Projects_DB` にイベントを作るときの決まりごと。
Claude もここに従って作成・更新します。

> **なぜ つなげーと と Notion の両方で管理しているか**
> Notion 側は**確定申告で使う情報**として運用しているためです。
> 二重管理に見えますが目的が違うので、この運用は変えません（改良も当面ペンディング）。

---

## 1. `ep_*` プロパティは使わない

`ep_` プレフィックスのプロパティは、イベントプラットフォームのアプリ作成時に使ったものです。
**現在の運用では使いません。** `TEST_Event_Projects_DB` / `Tickets_DB` / `Venues_DB` すべてで同じ扱いです。

- `ep_*` を読まない・書かない
- 新しくプロパティを足すときも `ep_` を付けない

---

## 2. タイトルの形式

```
YYMM-種別_イベント名
```

| 要素 | 内容 |
|---|---|
| `YYMM` | 開催年月の下2桁＋月2桁（2026年10月 → `2610`） |
| `種別` | `ID` / `OD` / `FD` の3種類 |
| `イベント名` | 企画名 |

| 種別 | 意味 |
|---|---|
| `ID` | インドア |
| `OD` | アウトドア |
| `FD` | フード（**フードがメインならこれ**） |

例: `2610-ID_ボードゲーム会` / `2611-FD_日本酒会` / `2604-OD_お花見`

---

## 3. プロパティの入力ルール

| プロパティ | 入力 |
|---|---|
| `イベント項目`（タイトル） | 上記2の形式を守る |
| `開催年度` | **必須** |
| `開催月` | **必須** |
| `開催予定期間` | **必須**（開始・終了の時刻まで） |
| `イベントタイプ` | **必須** |
| `進捗状況` | 下記4のとおり |
| `参加窓口` | つなげーとの対象イベントURL。**下書き作成後に入力**（下書きでもURLは発行される） |
| `確定申告判定` | **つなげーと経由のイベントはすべて「対象」** |
| `優先度` | すべて「中」でよい |
| `会場情報` | `Venues_DB` へのリレーション |
| `詳細` / `関連資料` / `関連サークル` | 任意 |
| `参加者・関係者` | **記載不要** |
| `確定日時` | **記載不要** |
| `関連タスク` | **記載不要** |

---

## 4. 「進捗状況」の遷移

| タイミング | ステータス |
|---|---|
| つなげーとでイベント作成**前** | `企画・計画中` |
| つなげーとでイベント作成**後** | `進行中` |
| 確定申告の記入後 | `完了` |

**`完了` は確定申告の記入後に人が付けるものです。Claude が勝手に `完了` にしない。**

`進捗状況` は「つなげーとに作成済みか」の判定にも使います。
`企画・計画中` = 未作成、`進行中` = 作成済み。

---

## 5. ページ本文「イベント概要」の書き方

参加費・定員・募集タイトル・メイン画像は、**プロパティではなくページ本文**に書きます。
参加費が早割・通常など複数になるため、プロパティ管理だと複雑になるからです。

表記ゆれで壊れないよう、**`【】` で囲んだキーワードを目印**にします。
`【】` は本文の他の場所では使わないでください。

### 書式

```
## イベント概要

【募集タイトル】横浜ではじめましてのボードゲーム会
【メイン画像】https://example.com/images/2610-boardgame.png
【定員】12

【参加費】
| チケット名 | 価格 | 定員 | 販売期限 |
|---|---|---|---|
| 早割 | 2500 | 5 | 2026-10-05 23:59 |
| 通常 | 3000 | 7 |  |
```

### 各キーワードの決まり

| キーワード | 内容 | つなげーとAPI |
|---|---|---|
| `【募集タイトル】` | 1行。**つなげーとに出す公開用のタイトル**（`イベント項目` は管理用の名前なので別物） | `event[title]` |
| `【メイン画像】` | 1行。`https://` で始まる**恒久URL**。省略可（省略＝画像なし） | `main_image_url` |
| `【定員】` | 1行。**数値のみ**（`12`。「名」は付けない） | — |
| `【参加費】` | 直後の表を読む。行が1つでも表で書く | `events_plans[]` |

### 参加費テーブルの列

| 列 | 内容 |
|---|---|
| `チケット名` | 早割 / 通常 など |
| `価格` | 数値のみ（`2500`。「円」やカンマは付けない） |
| `定員` | そのチケットの枚数。数値のみ |
| `販売期限` | `YYYY-MM-DD HH:MM`。無期限なら空欄 |

### 読み取り時の検査

- `【募集タイトル】` が無ければ**止める**。推測で埋めない
- `【参加費】` の表が無ければ**止める**。
  つなげーとAPIはプランを省略すると**無料プラン1件を自動生成**するため、
  有料の回で表を忘れると無料イベントとして公開されうる
- 各チケットの `定員` の合計が `【定員】` と合わなければ**指摘する**
- `【メイン画像】` のURLは事前に到達確認する。
  取得に失敗するとリクエスト全体が 422 で落ちるため（`docs/tunagate-api.md`）
- **Notion添付の署名付きURL（`prod-files-secure.s3...`）は数分で失効するので使わない**

## 6. 募集本文

つなげーとの `body`（本文）は、ページ本文の **`## 募集本文`** 見出し以下をそのまま使います。
`brand/voice.md` のトンマナに従い、`brand/rules.md` の参加規約とキャンセルポリシーを差し込みます。

## 8. やらないこと

**イベントタスクの細分化はしません。**
細かく分けても運用で使われず、管理が複雑になった経験があるためです。
`関連タスク` リレーションは記載不要で、タスクの自動生成も行いません。
