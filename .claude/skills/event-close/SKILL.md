# 開催後の締め

振り返りは「やらずに終わる」のが常なので、開催直後に一気に片づけます。

## 手順

1. **対象イベントを特定する。** `events/` から直近のものを探す。複数候補があれば確認する。

2. **実績値を聞く。** 一度にまとめて聞く。
   実参加者数 / 当日キャンセル数 / うち初参加 / 実際の支出 / アンケート結果（あれば）

3. **`pl.md` の確定値を埋める。** 事前シミュレーションと比べ、差が出た理由を一言添える。

4. **分配を計算する。**（C型で運用している場合）
   `finance/profit-share.md` のルールに従って計算し、`pl.md` の分配表を埋める。
   ルールの TODO が埋まっていない場合は、計算せずにその旨を指摘する。

5. **`finance/ledger.csv` に転記する。** 収入・支出・分配を行として追加する。

6. **`retro.md` を書く。**
   - `plan.md` の「成功の定義」に対して YES / NO を明示する
   - 改善点は**3つまで**に絞る。多いと実行されない
   - 運営メンバー候補は**ニックネームのみ**で記録する

7. **お礼文と次回告知の下書き**を作る。

8. **イベントレポ記事の下書き**を `content/` に作る。記憶が新しいうちに書けるのが最大の利点。
   写真掲載NGの参加者がいる場合は、記事の冒頭に注意書きを残す。

## 守ること

- 参加者の本名・連絡先を `retro.md` にも記事にも書かない
- アンケートの否定的な意見を丸めない。そのまま残す
- 赤字だった場合は、原因（集客・原価・当日キャンセル）を切り分けて書く
