# 身内イベント（クローズ会）の作成

つなげーとを経由しない回のためのコマンドです。`/event-repeat` と同じ `TEST_Event_Projects_DB` に、
同じ作成ルール（タイトル形式・必須プロパティ）でページを作ります。

**`/event-repeat` との違いはページ本文です。** つなげーとの公開ページが無い分、
**Notion ページ本文そのものが参加者向けの案内**になります。参加者がこのページを直接見て
参加を判断・準備できるように、日時・場所・参加費・注意事項・キャンセルポリシーを本文に
書き切ります（`docs/notion-event-rules.md` 6.5 の「つなげーと経由イベントは本文を空にする」
方針はここでは適用しません。つなげーとを経由しないため公開ページが存在しないからです）。

作業の前に `brand/voice.md` `brand/rules.md` `docs/notion-event-rules.md` を読むこと。

## 手順

### 1. 内容を確認する

次が揃っているか確認し、足りないものだけをまとめて1回で聞く。**推測で埋めない。**

- 企画内容（何をする会か）
- 日程（開始・終了の日時）
- 場所（最寄駅・会場名。個人宅などの詳細住所は、参加者だけに見せてよいか本人に確認する）
- 定員
- 参加費（**固定額**。早割・人数枠などの差はつけない。内訳があれば併記）
- 対象・年齢制限（飲酒を伴う回は20歳以上）
- 主催者からの一言（任意）

会場が `Venues_DB` にある候補なら提示する。個人宅・知人の店など台帳に無い場所は、
本文にそのまま書いてよい（つなげーとを経由しないため `docs/tunagate-api.md` の制約は関係ない）。

不明な値は `TODO:` として残し、埋めた体で進めない。

### 2. Notion ページを作る

`TEST_Event_Projects_DB` に新規ページを作成する。**`ep_*` プロパティには触れない。**

| 項目 | 入れるもの |
|---|---|
| タイトル | `YYMM-種別_イベント名`（種別は `ID` / `OD` / `FD`） |
| `開催年度` `開催月` `開催予定期間` `イベントタイプ` | 必須。1つでも欠けたら未完成 |
| `会場情報` | `Venues_DB` にある会場ならリレーション。無ければ空のまま、本文の「場所」に書く |
| `進捗状況` | 作成時は `企画・計画中`。本文が完成し参加者に共有できる状態になったら `進行中` |
| `確定申告判定` | **自動で「対象」にしない。** つなげーと経由の回のようにルールが定まっていないため（`docs/notion-event-rules.md` 5参照はつなげーと経由の場合のみ）。参加費のやり取りがあることを伝えたうえで、ユーザーに確認するか `TODO:` で残す。判定そのものを断定しない（`CLAUDE.md` の絶対ルール2） |
| `優先度` | `中` |
| `参加窓口` | 空のまま作成し、ページ作成後に**このページ自身のURL**を入れる（つなげーとの代わりに、このページが参加者の窓口になるため） |
| `参加者・関係者` `確定日時` `関連タスク` | **入れない**（`docs/notion-event-rules.md` 8） |

### 3. 本文を「参加者がそのまま読める案内」として書く

つなげーとの本文が無い分、次を**すべて**本文に含める。`brand/voice.md` の募集文必須9項目に、
クローズ会特有の2点（★）を足したもの。

1. 導入（2〜3文。どんな会か・誰向けか）
2. 日時
3. 場所（最寄駅まで。詳細住所は「参加者にのみ個別にご案内」でも、そのまま書いてもよい。
   本人に確認した方針に従う）
4. 定員
5. ★参加費（**固定額であることを明記**。「参加順によらず〇〇円」のように書く。内訳があれば添える）
6. 当日の流れ
7. 対象（年齢制限を含む）
8. 注意事項（`brand/rules.md` の参加規約から、この回に関係する項目を抜粋。
   勧誘禁止・写真掲載可否・飲酒に関する項目は基本的に外さない）
9. ★キャンセルについて（`brand/rules.md` 9番のキャンセルポリシーをそのまま使う。
   書き換えない）
10. 主催者からの一言

トンマナは `brand/voice.md` に従う。「恋活」「婚活」「出会い」は使わない。
「絶対に」「必ず」などの断定も避ける。身内向けだからと丁寧さを省略しない
（参加者はこのページを直接読む）。

### 4. 参加者への共有について確認する

つなげーとを経由しないため、公開・非公開の設定は完全に人の判断になる。
ページ作成後、次を必ずユーザーに伝えて止まる。

- Notion ページの共有範囲（リンクを知っている人のみ閲覧可、など）は Claude 側では設定できない。
  **人がNotion側で共有設定を行うこと**
- 参加費の集金方法（当日現金／送金など）はこのコマンドの範囲外。ユーザーに確認する

### 5. 最後に出すもの

- Notion ページのURL
- **人がやること**: ①Notionページの共有範囲を設定 ②参加者への送付（LINEなど）
  ③参加費の集金方法を決める ④（`確定申告判定` が `TODO:` のままなら）判定の確認

## 守ること

- `ep_*` プロパティを読まない・書かない
- `進捗状況` を `完了` にしない。`完了` は確定申告の記入後に人が付ける
- `確定申告判定` を機械的に「対象」にしない。断定せず、必要なら「専門家に確認」を添える
- 「恋活」「婚活」「出会い」を本文に使わない
- 参加者の個人情報（本名・電話番号・メール・住所・勤務先）を書かない。
  ニックネーム・参加回数・写真掲載可否までにとどめる
- 参加費は固定額として書く。早割・段階制など「参加順に左右される」設計にしない
- キャンセルポリシーは `brand/rules.md` のものをそのまま使う。独自に緩めたり厳しくしたりしない
- 金額・日付・人数・場所を推測で確定しない
- 飲酒を伴う回は対象を20歳以上にする

## `/event-repeat` `/event-new` との違い

| | `/event-repeat` `/event-new` | `/event-private` |
|---|---|---|
| 経路 | つなげーと | 経由しない |
| Notion本文 | 空、または元イベントへのリンクのみ | 参加者向け案内をフルで書く |
| 参加費 | 早割など複数プラン可 | 固定額のみ |
| `参加窓口` | つなげーとのイベントURL | このNotionページ自身のURL |
| 公開範囲の設定 | つなげーとの公開ボタン（人が押す） | Notionの共有設定（人が行う） |
| `確定申告判定` | すべて「対象」 | 断定せず確認する |

## つまずきやすいところ

| 症状 | 原因 |
|---|---|
| 参加者がページを開けない | Notionの共有設定が「リンクを知っている人のみ」になっていない。Claudeは共有設定を変更できないため、人が確認する |
| 参加費の説明で早割・段階制のような書き方になってしまう | クローズ会は固定額が前提。書き方をテンプレの表形式（つなげーと用）から流用しない |
| `確定申告判定` を反射的に「対象」にしてしまう | それは「つなげーと経由」の場合のルール。ここでは断定しない |
